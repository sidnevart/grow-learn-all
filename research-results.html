Token Economy Kit

Набор инструментов, который сокращает расход токенов Claude — автоматически, без изменений в работе разработчика.

В чём проблема

Claude работает с контекстным окном — конечным пространством, куда помещаются все данные сессии. Каждый токен в контексте стоит денег. Проблема в том, что без оптимизации туда попадает огромное количество лишних данных: полные git-диффы, тысячестрочные деревья директорий, XML-файлы с метаданными тестов.

Больше лишних данных → больше токенов → выше стоимость → хуже качество ответов, потому что модель «отвлекается» на шум.

Каждый из этих сценариев — это то, что Claude делает регулярно в ходе работы. Без оптимизации разработчик не замечает расход, но деньги утекают.

Как это работает

Три уровня, которые работают вместе. Разработчику не нужно знать об их существовании.

🔀
Прокси — claude-token-buffet
Все запросы от Claude Code проходят через общий прокси вместо прямого обращения к Anthropic API. Прокси знает: кто сделал запрос, какую модель использовал, сколько токенов потратил, сколько это стоит. Всё пишется в PostgreSQL и видно в Grafana.
Прозрачно для разработчика
⚡
Хуки — автоматический перехват
Claude Code поддерживает хуки: скрипты, которые запускаются до выполнения инструментов. Когда Claude собирается запустить tree, git diff или rg — хук перехватывает команду, запускает сжатую версию и блокирует оригинал. Claude видит только компактный результат.
Полностью автоматически
📋
CLAUDE.md — правила поведения
Файл с инструкциями, который Claude читает в начале каждой сессии. Там написано: «перед изучением кодовой базы запусти repo-map», «если вывод больше 50 KB — сохрани в context-store». Claude следует этим правилам без напоминаний.
Claude следует сам
Разработчику достаточно один раз запустить установочный скрипт. После этого все три уровня работают в фоне.

Инструменты: сжатие команд

Эти инструменты работают полностью автоматически через хуки. Когда Claude запускает дорогую команду — хук подменяет её на сжатый вариант. Claude не знает о подмене, просто получает компактный ответ.

diff-pack до 24×
Сжимает git diff. Вместо 1.8 MB кода — список файлов со счётчиками изменений и названиями функций. Агент понимает масштаб PR без чтения каждой строки.
git diff HEAD~5 → 73 KB вместо 1.8 MB
⚡ автоматически
tree-pack до 1 828×
Заменяет tree. Возвращает компактную сводку: модули, примеры src/main и src/test, конфиги, build-файлы. Всё это в ~1 700 байт независимо от размера репозитория.
tree ./src → 1 730 байт вместо 3.2 MB
⚡ автоматически
rg-pack 2–5×
Оборачивает rg и grep. Вместо потока строк — список файлов с количеством совпадений, 1–3 примера на файл и список «что читать дальше».
rg "KafkaListener" . → структурированный список
⚡ автоматически
test-summary до 1 240×
Читает JUnit XML (Gradle/Maven), Go и pytest отчёты. Возвращает: сколько тестов, сколько упало, для каждого упавшего — название, ошибка, файл и строка.
140 KB XML → 113 байт, только суть
⚡ автоматически
log-pack до 9.6×
Дедуплицирует логи. Убирает повторяющиеся сообщения, нормализует request_id, показывает уникальные ошибки с количеством повторений и ссылкой на файл.
9.6 KB build log → 997 байт уникальных ошибок
⚡ автоматически

Инструменты: контекст задачи

Эти инструменты помогают Claude понять кодовую базу без чтения сотен файлов. Работают через правила в CLAUDE.md — Claude использует их сам, когда это уместно.

repo-map ~40 000×
Сканирует репозиторий статически и возвращает карту символов: классы, интерфейсы, функции, Kafka listeners, контроллеры, репозитории. Вместо чтения 288 файлов — 798 байт с картой всего проекта.
288 .go файлов → 798 байт карты
📋 по правилу CLAUDE.md
task-pack старт задачи
Собирает компактный «брифинг» задачи: описание, критерии готовности, релевантные символы из repo-map, последние изменения из diff, упавшие тесты. Claude получает структурированный контекст вместо свободного описания.
issue + map → 1 876 байт брифинга
📋 по правилу CLAUDE.md

Инструменты: управление контекстом

context-store хранилище
Когда Claude получает большой вывод (>50 KB), сохраняет его локально и возвращает ID + краткое резюме. Дальше в сессии Claude оперирует summary и обращается к деталям только если нужно.
5.4 KB diff → id: out_20260504_xxx + summary
📋 по правилу CLAUDE.md
budget-guard советник
Проверяет команды до выполнения и предупреждает о потенциально дорогих операциях. Предлагает дешёвую альтернативу: вместо git diff HEAD~10 → diff-pack.
git diff HEAD~10 → «риск: используй diff-pack»
⚡ автоматически через хук
token-metrics аналитика
Анализирует JSONL-лог сессий: общий расход токенов, стоимость, cache hit ratio, сравнение периодов. Показывает, насколько эффективна оптимизация на реальных данных.
baseline 609K → optimized 286K токенов

Как работает хук (технически)

Хук — это скрипт, который Claude Code запускает до выполнения инструмента. Если хук завершается с кодом 2, оригинальная команда не выполняется. Claude видит только вывод хука — уже сжатые данные.

# ~/.claude/token-economy/hooks/pre-bash.sh
CMD=$(cat - | jq -r '.command')

case "$CMD" in
  tree\ *)
    ARGS="${CMD#tree }"
    ~/.claude/te-kit/scripts/tree-pack $ARGS
    exit 2   # ← Claude не видит сырой tree
    ;;
  "git diff"*)
    eval "$CMD" | ~/.claude/te-kit/scripts/diff-pack --stat
    exit 2   # ← Claude не видит 1.8 MB диффа
    ;;
esac
exit 0  # остальные команды не трогаем

Метрики в Grafana

Все запросы проходят через claude-token-buffet — прокси, который уже перехватывает и считает токены. Добавление записи в PostgreSQL — это несколько строк в существующем методе applyUsage(). После этого данные доступны в Grafana.

Time series
Токены по времени
Расход input + output токенов в разрезе дней и часов. Сразу видно когда и насколько вырос расход.
Bar gauge
Cache hit %
Доля токенов, прочитанных из кэша. Ключевая метрика эффективности — должна расти со временем после подключения оптимизаций.
Table
Стоимость по пользователям
Кто сколько тратит, какую модель использует, какой cache hit у каждого. Помогает находить неэффективные паттерны.

Схема данных (PostgreSQL)

CREATE TABLE token_requests (
    ts                    TIMESTAMPTZ DEFAULT NOW(),
    user_name             TEXT,
    model                 TEXT,
    input_tokens          BIGINT,
    output_tokens         BIGINT,
    cache_read_tokens     BIGINT,
    cache_creation_tokens BIGINT,
    cost_usd              NUMERIC(12, 6)
);

Prometheus-метрики уже доступны на порту :2112 прямо сейчас — базовые графики можно подключить без PostgreSQL. БД нужна для истории дольше 15 дней и SQL-аналитики.

Как подключить

Два шага. Второй шаг — одна команда.

  1. Получить доступ к прокси Попросить токен у команды и добавить одну переменную окружения. Все запросы Claude Code пойдут через общий прокси — появится трекинг и управление расходами. 
    # ~/.zshrc или ~/.bashrc
export ANTHROPIC_BASE_URL=http://claude-token-buffet.internal:3001
export ANTHROPIC_API_KEY=your-team-token
  2. Запустить установочный скрипт Скрипт кладёт scripts/ в ~/.claude/token-economy/, добавляет хуки в ~/.claude/settings.json и правила в ~/.claude/CLAUDE.md. После этого экономия работает сама. 
    curl -sSL https://internal/install-token-economy.sh | bash
После установки: следующий git diff в Claude Code будет автоматически сжат. Следующий tree — заменён. Разработчик этого не заметит, но токенов потратит втрое меньше.
