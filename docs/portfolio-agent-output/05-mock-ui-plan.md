# 05 Mock UI Plan

## Overview

This document maps every project that requires a mock frontend to its specific visual representation strategy. Each project gets screen recommendations, synthetic data rules, component requirements, and labeling guidelines. The goal is to communicate backend complexity through realistic UI surfaces without implying these are production frontends.

## Project: AI Code Review for GitLab

### Recommended Screen Mockups

1. **Merge Request List Dashboard**

   - Top bar with project selector and filter tabs (Open / Merged / Needs Attention).

   - Expandable list of detected issues per file.

   - Timeline of actions: AI Review Submitted → Developer Comments → Revised → Approved.
   - Comment thread with avatar initials, timestamps, and resolution status.

## Reusable Component Specifications

### BrowserMockup

**Props**:
- `url` (string): Displayed in address bar.
- `children` (ReactNode): Content rendered inside.
- `showAddressBar` (boolean, default true): Show/hide address bar.
- `showTabs` (boolean, default false): Show tab bar above address bar.
- `tabTitle` (string): Title for single tab.
- `darkTheme` (boolean, default true): Use dark inner background.
- `height` (number, optional): Fixed content height in px.

**Structure**:
```
<BrowserMockup>
  <div className="browser-frame">
    <div className="title-bar">
      <div className="traffic-lights" />
      <div className="address-bar">{url}</div>
      <div className="window-controls" />
    </div>
    <div className="content-area">{children}</div>
  </div>
</BrowserMockup>
```

**Styling**:
- Frame: `--bg-secondary`, 1px `--bg-quaternary` border, 12px radius.
- Title bar: 36px, `--bg-tertiary`, flex row, space-between.
- Traffic lights: 12px circles, `--accent-error`, `--accent-warning`, `--accent-success`.
- Address bar: `--bg-primary`, 6px radius, `caption` size, `--text-tertiary`, max-width 400px centered.
- Content area: `--bg-primary`, no radius on bottom corners, min-height 300px.

**Default text**:

- Footer: "Demo interface — synthetic data"

## Cross-Cutting Labeling Rules

Every mock UI in the portfolio must follow these labeling conventions:

1. **Primary Badge**: Every mockup container gets a `DemoDataNotice` badge in the top-right corner with variant "badge".
2. **Contextual Banner**: For complex multi-screen projects, add a `DemoDataNotice` banner inside the BrowserMockup title bar or below it.
3. **Footer Text**: Every project section in the portfolio page includes a `DemoDataNotice` footer below the gallery.
4. **Color Coding by Project Type**:
   - AI/Agent projects: `--accent-purple`
   - Automation/CI projects: `--accent-orange`
   - Data/Analytics projects: `--accent-info`
   - Telegram/Mobile projects: `--accent-success`
   - University/Game projects: `--accent-warning`
5. **No Ambiguity**: The word "Mock" or "Demo" must appear at least once per project section in visible text (not just alt tags).
6. **Metric Disclaimers**: Any metric that looks real ("5x faster", "$600K+") in a mock must have an asterisk or tooltip explaining it is a representative example.
